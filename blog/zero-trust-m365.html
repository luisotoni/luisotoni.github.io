Microsoft 365 Zero Trust Security

Implementando Zero Trust com Microsoft 365

👤 Luís Otoni 📅 05 de Novembro de 2025 ⏱️ 15 min de leitura 📁 Segurança

O modelo Zero Trust revolucionou a forma como pensamos segurança. Em vez de confiar em perímetros de rede, Zero Trust assume que ameaças podem vir de qualquer lugar - dentro ou fora da organização. Neste guia, vou mostrar como implementar Zero Trust usando as ferramentas do Microsoft 365.

O Que é Zero Trust?

Zero Trust é um framework de segurança baseado no princípio "nunca confie, sempre verifique". Os três pilares fundamentais são:

  • Verificar explicitamente: Sempre autenticar e autorizar baseado em todos os pontos de dados disponíveis
  • Usar menor privilégio: Limitar acesso do usuário com Just-In-Time e Just-Enough-Access (JIT/JEA)
  • Assumir violação: Minimizar blast radius e segmentar acesso; verificar criptografia end-to-end

Arquitetura Zero Trust Microsoft

A Microsoft organiza Zero Trust em seis áreas fundamentais:

  • Identidades: Verificar e proteger cada identidade
  • Dispositivos: Garantir que dispositivos estejam saudáveis e compliant
  • Aplicações: Descobrir shadow IT e controlar acesso
  • Dados: Classificar, rotular e proteger dados sensíveis
  • Infraestrutura: Detectar ataques e anomalias
  • Rede: Segmentar e usar criptografia

1. Protegendo Identidades

A identidade é o novo perímetro de segurança. Comece aqui.

Multi-Factor Authentication (MFA)

MFA é o primeiro e mais importante passo. Implementação recomendada:

  • Habilite MFA para 100% dos usuários, sem exceções
  • Prefira Microsoft Authenticator com number matching
  • Bloqueie métodos fracos como SMS quando possível
  • Use Security Defaults se não tiver Azure AD Premium
  • Com Azure AD Premium, use Conditional Access para controle granular

Conditional Access

Conditional Access é o motor de decisão do Zero Trust. Políticas essenciais:

Política 1: Require MFA for All Users

  • Users: All users (exceto break-glass accounts)
  • Cloud apps: All cloud apps
  • Conditions: Any
  • Grant: Require MFA

Política 2: Block Legacy Authentication

  • Users: All users
  • Cloud apps: All cloud apps
  • Conditions: Client apps → Other clients
  • Grant: Block access

Política 3: Require Compliant Devices

  • Users: All users
  • Cloud apps: Office 365
  • Conditions: Any device platform
  • Grant: Require device to be marked as compliant

Política 4: Block High-Risk Sign-ins

  • Users: All users
  • Cloud apps: All cloud apps
  • Conditions: Sign-in risk = High
  • Grant: Block access

Identity Protection

Azure AD Identity Protection detecta riscos automaticamente:

  • User risk: Credenciais vazadas, padrões de uso anormais
  • Sign-in risk: Impossible travel, IPs maliciosos, device malware

Configurações recomendadas:

  • User risk policy: High risk → Require password change + MFA
  • Sign-in risk policy: Medium+ risk → Require MFA
  • Configure alertas para investigação

Privileged Identity Management (PIM)

Just-In-Time access para administradores:

  • Remova atribuições permanentes de admin roles
  • Configure eligible assignments com aprovação
  • Defina duração máxima de ativação (ex: 8 horas)
  • Exija justificativa e MFA para ativação
  • Configure alertas para ativações

2. Protegendo Dispositivos

Dispositivos não confiáveis não devem acessar dados corporativos.

Microsoft Intune - Compliance Policies

Defina o que significa um dispositivo "saudável":

  • Sistema operacional mínimo (ex: Windows 11 22H2)
  • Antivírus ativo e atualizado
  • Firewall habilitado
  • BitLocker/criptografia ativo
  • Não rooted/jailbroken
  • PIN/senha configurado

Microsoft Defender for Endpoint

EDR (Endpoint Detection and Response) para proteção avançada:

  • Deploy em todos os endpoints corporativos
  • Configure automated investigation and response
  • Integre com Conditional Access (machine risk level)
  • Use attack surface reduction rules
  • Configure web content filtering

Enrollment e MAM/MDM

  • Corporate devices: Full MDM enrollment via Intune
  • BYOD: MAM (Mobile Application Management) para proteger apps sem gerenciar device
  • Use App Protection Policies para dados corporativos
  • Configure conditional launch para bloquear devices comprometidos

3. Protegendo Aplicações

Microsoft Defender for Cloud Apps (MCAS)

Visibilidade e controle sobre aplicações cloud:

  • Shadow IT Discovery: Identifique apps não sancionados
  • App Governance: Controle apps OAuth conectados
  • Session Control: Monitore e controle sessões em tempo real
  • Anomaly Detection: Detecte comportamentos suspeitos

Conditional Access App Control

  • Bloqueie download de dados sensíveis em dispositivos não gerenciados
  • Force watermark em documentos visualizados
  • Monitore atividades em tempo real
  • Bloqueie copy/paste de dados corporativos

4. Protegendo Dados

Microsoft Information Protection (MIP)

Classifique e proteja dados sensíveis:

  • Sensitivity Labels: Public, Internal, Confidential, Highly Confidential
  • Auto-labeling: Aplique labels automaticamente baseado em conteúdo
  • Encryption: Proteja documentos mesmo fora da organização
  • Rights Management: Controle quem pode ler, editar, imprimir

Data Loss Prevention (DLP)

  • Crie políticas para detectar dados sensíveis (CPF, cartão de crédito, etc.)
  • Bloqueie compartilhamento externo de dados confidenciais
  • Configure DLP em Exchange, SharePoint, OneDrive, Teams, Endpoints
  • Use policy tips para educar usuários

5. Protegendo Email

Microsoft Defender for Office 365

  • Safe Attachments: Detonação de anexos em sandbox
  • Safe Links: Verificação de URLs em tempo de clique
  • Anti-phishing: Proteção contra impersonation
  • Attack Simulation: Treine usuários com phishing simulado

Exchange Online Protection

  • Configure SPF, DKIM, DMARC
  • Use Enhanced Filtering for Connectors
  • Configure quarantine policies
  • Block auto-forwarding para domínios externos

6. Monitoramento e Resposta

Microsoft 365 Defender Portal

Console unificado para investigação e resposta:

  • Incidents: Visão correlacionada de alertas
  • Hunting: Query proativa de ameaças
  • Threat Analytics: Intelligence sobre ameaças atuais
  • Secure Score: Meça e melhore sua postura

Microsoft Sentinel

SIEM cloud-native para organizações maiores:

  • Colete logs de todas as fontes (M365, Azure, on-prem, terceiros)
  • Use analytics rules para detecção
  • Automatize resposta com playbooks (Logic Apps)
  • Investigue com notebooks e hunting queries

Roadmap de Implementação

Fase 1: Fundação (Semanas 1-4)

  • ☑️ Habilitar MFA para todos os usuários
  • ☑️ Bloquear legacy authentication
  • ☑️ Configurar break-glass accounts
  • ☑️ Implementar Security Defaults ou CA básico

Fase 2: Identidade Avançada (Semanas 5-8)

  • ☑️ Configurar Identity Protection
  • ☑️ Implementar PIM para admins
  • ☑️ Criar políticas de Conditional Access avançadas
  • ☑️ Configurar Access Reviews

Fase 3: Dispositivos (Semanas 9-12)

  • ☑️ Enrollment de dispositivos no Intune
  • ☑️ Criar compliance policies
  • ☑️ Deploy Defender for Endpoint
  • ☑️ Integrar device compliance com CA

Fase 4: Dados e Apps (Semanas 13-16)

  • ☑️ Implementar sensitivity labels
  • ☑️ Configurar DLP policies
  • ☑️ Deploy Defender for Cloud Apps
  • ☑️ Configurar session controls

Métricas de Sucesso

  • MFA Coverage: 100% dos usuários usando MFA
  • Legacy Auth: 0% de sign-ins usando legacy protocols
  • Secure Score: Melhorar continuamente (meta: >80%)
  • Incident Response: Reduzir mean time to respond (MTTR)
  • Device Compliance: >95% de dispositivos compliant

Conclusão

Zero Trust não é um produto que você compra, mas uma jornada de transformação da segurança. Microsoft 365 fornece todas as ferramentas necessárias para implementar Zero Trust de forma abrangente.

Comece pelos fundamentos (MFA, block legacy auth), avance para controles mais sofisticados (CA, device compliance), e evolua continuamente baseado em ameaças e necessidades do negócio.

Lembre-se: Segurança é uma jornada, não um destino. Zero Trust é sobre melhoria contínua e adaptação a um cenário de ameaças em constante evolução.
