Conditional Access in 2026: What Changed

👤 Luís Otoni 📅 September 3, 2026 ⏱️ 9 min read 📁 Security

Microsoft changed more in Conditional Access in 2026 than in any recent year — and a good chunk of these changes alter how policies already running in production behave, without anyone needing to touch anything. Here's what actually matters, what each change implies in practice, and what's worth reviewing right now.

1. Security for AI agents

Conditional Access gained specific controls for AI agent accounts (Copilot agents and similar scenarios). Admins can now include or exclude agents from policies with precision, apply rules based on agent risk, and require compliant devices — including Windows 365 for Agents scenarios.

This came with new license plans ("Conditional Access for agents" and "ID Protection for agents"), available through Microsoft Agent 365 and Microsoft 365 E7. Rollout began in early July 2026 and was expected to complete by early August.

Practical implication: if the organization already uses AI agents with their own accounts (not just humans interacting through Copilot), those accounts are likely outside the scope of current Conditional Access policies. Worth mapping which agents exist in the tenant and deciding whether they fall under existing policies or dedicated ones.

2. Stricter enforcement for "All resources" policies with exclusions

Since June 15, 2026, Conditional Access policies targeting "All resources" are now enforced for client application sign-ins as well, even when resource exclusions are present in the policy.

Practical implication: this closes a real gap. Previously, a specific resource exclusion could unintentionally let a client-app sign-in scenario slip through that should've been covered by the broader policy. If you (or a client) have "All resources" policies combined with exclusions, behavior may have quietly changed in June — worth testing again rather than assuming it's unchanged.

3. Conditional Access now applies during credential registration

Starting July 13, 2026, policies targeting the "Register security info" action also apply to Windows Hello for Business provisioning and macOS Platform Single Sign-on registration — scenarios that were previously out of scope for these policies.

Practical implication: if you have a restrictive policy on "Register security info" (for example, requiring a trusted network or managed device), it now reaches more scenarios than it did before July. Worth validating that legitimate users aren't blocked while provisioning Windows Hello or macOS SSO.

4. Passkeys as the default authentication method

Microsoft is pushing passkeys as the default authentication method throughout 2026, part of a broader wave of Entra ID security updates (which also includes replacing Custom controls with External MFA).

Practical implication: the official recommendation is to audit existing Conditional Access policies before full rollout, specifically to ensure backend service endpoints aren't unintentionally blocked during passkey enrollment — one of the most commonly reported conflicts from organizations that already went through this transition.

5. SSPR will only accept formally registered methods

Starting November 9, 2026, self-service password reset will stop accepting phone numbers or email addresses that only exist in the directory but were never formally registered by the user as an authentication method.

Practical implication: this is the change with the highest potential to generate a wave of support tickets if not communicated ahead of time. Worth running a report on how many users currently rely on unregistered methods for SSPR, and running a registration campaign before November — not after.

6. New License Usage page

The Microsoft Entra admin center gained a license usage visibility page (Microsoft Entra ID P1, P2, and Suite), cross-referenced with real usage metrics for features like Conditional Access and risk-based Conditional Access.

Practical implication: it's a useful tool to justify a licensing upgrade with real usage data instead of estimates — worth bringing into your next security budget conversation.

What To Do Now

  • Map which AI agents exist in the tenant and decide their policy coverage
  • Review (and re-test) "All resources" policies that have resource exclusions
  • Validate that "Register security info" policies don't block legitimate Windows Hello or macOS SSO provisioning
  • Audit Conditional Access policies for conflicts with passkey enrollment
  • Identify how many users rely on unregistered SSPR methods, before November 9
  • Use the License Usage page to support licensing decisions
